# 2026-07-22

Claude CodeはRC寸前の安定化フェーズに入り2.1.216/217で地味だが実務に効くセキュリティ・パフォーマンス修正が続く一方、Swift EvolutionはInlineArrayのHashable化やCodableプロトコルの標準ライブラリ入りなど小粒だが着実な提案が動く。米半導体株の急伸が21日の東京市場にも波及しアドバンテスト・キオクシアが急騰、iOS 27はベータ4・26.6はRCと年次リリース前の最終調整段階に入った。

## AI（Anthropic / OpenAI）

- **Claude Code 2.1.216/2.1.217、バックグラウンドセッションのシンボリックリンク検証などセキュリティ・安定性修正が連続（7/20〜21）**：2.1.216で`sandbox.filesystem.disabled`設定の追加や長時間セッションでのメッセージ正規化コストが2乗で増大する速度低下を修正、2.1.217ではバックグラウンドセッション分離がシンボリックリンクされた作業ディレクトリを正しく正規化していなかったセキュリティ上の不具合や、MCPツール出力の切り詰め後も全文がメモリに残るメモリリークを修正した。サブエージェントの同時実行数上限（デフォルト20、`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`で変更可）も新設され、無制限なエージェント増殖を防ぐ。日常的にClaude Codeを使う開発者はアップデートの価値がある。
  - [https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#2-1-217](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#2-1-217)

- **OpenAI Codex、GPT-5.6 Sol/Terra/Luna向けの同梱指示を更新しコンテキストウィンドウを27.2万トークンに修正（7/18）**：バンドルされているシステム指示を刷新し、誤って告知されていたコンテキストウィンドウ値を27.2万トークンに正した。加えて危険なコマンド検出を強化し、より多様な`rm`の破壊的パターンを検知して拒否理由を明示するようになった。CI/CDにCodexを組み込んでいるチームはコンテキスト長の前提を再確認する価値がある。
  - [https://developers.openai.com/codex/changelog](https://developers.openai.com/codex/changelog)

- **OpenAI Responses API、Web検索ツールに`return_token_budget`パラメータを追加**：GPT-5以降の高負荷なリサーチ・評価ワークロード向けに、より長時間の推論を伴うWeb検索実行をオプトインできるようになった。長文コンテキストの調査タスクをAPI経由で自動化しているエンジニアにとって、地味だが効くチューニング項目。
  - [https://developers.openai.com/api/docs/changelog](https://developers.openai.com/api/docs/changelog)

## Swift / Apple エコシステム

- **[Pull Request] InlineArrayをHashableに準拠させる提案（7/21）**：固定長配列`InlineArray`をハッシュベースのコレクションや辞書のキーとして使えるようにする変更が提案された。要素ごとの等価性と同一性のどちらでハッシュを計算すべきかという論点も議論されており、値型として`InlineArray`を積極活用しているコードベースでは今後の対応を追う価値がある。
  - [https://github.com/swiftlang/swift-evolution/pull/3367](https://github.com/swiftlang/swift-evolution/pull/3367)

- **[Draft] "Literate Swift"提案がドラフトとして提出（7/17）**：コードとドキュメントを一体化して記述する「literate programming」スタイルをSwiftに導入する初期提案。Language Steering Groupが7/20付けで正式にラベル付けし議論の俎上に載せた段階で、まだ具体的な構文は固まっていないが、ドキュメント生成やチュートリアル向けコードの書き方に一石を投じる可能性がある。
  - [https://github.com/swiftlang/swift-evolution/pull/3361](https://github.com/swiftlang/swift-evolution/pull/3361)

- **[Pull Request] `TopLevelEncoder`/`TopLevelDecoder`を標準ライブラリへ移動する提案（7/15）**：これまでswift-collections/Foundation周辺で提供されていたエンコーダ・デコーダの基底プロトコルを標準ライブラリ本体に取り込む提案。独自のシリアライズ形式やCodable関連ライブラリを実装しているエンジニアにとって、依存関係が減り移植性が上がる地味だが実用的な変更。
  - [https://github.com/swiftlang/swift-evolution/pull/3360](https://github.com/swiftlang/swift-evolution/pull/3360)
